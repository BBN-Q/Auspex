# Auspex V2 — current status

See [PLAN.md](PLAN.md) for design decisions and open questions. This is a **simulated/offline prototype**, not hardware-ready. V1 remains unchanged.

## Implemented

- V2 code and tests are grouped by subsystem: `auspex_v2/{experiment,data,filters,instruments}/` and matching `v2/tests/{experiment,data,filters,instruments}/`. Public package imports remain `auspex_v2.experiment` and `auspex_v2.data`; browser helpers live under `auspex_v2.data.browser`.

- Independent Python 3.13 package (`v2/`) with direct-use, targeted ports for `AgilentN5183A`, `YokogawaGS200`, `AgilentE8363C`, and `AgilentN5230A`. Optional VISA is imported only when needed. Fake transports test commands and complex VNA trace decoding; **no real hardware tests**.
- An explicitly started, persistent **instrument server** (`v2/src/auspex_v2/instruments/server/`) for `simulated_source` and `simulated_vna` only. It uses a permission-restricted Unix socket, a single-instance lock, saved inventory/run state, and one spawned process per connected device. No ExperimentServer yet.
- Separate **connection and ownership**: registration does not connect (`DISCONNECTED`); `connect(name)` or `run.connect(name)` is explicit. Live use requires `CONNECTED`; ending a live lease leaves it connected. A run locks *all* registered devices against live access, regardless of connection. A lost live client releases its lease; a lost run client leaves an orphaned lockout requiring `reconcile_run(reason)`.
- Failures of connect/disconnect latch `UNKNOWN`; worker deaths, command failures, and operator termination latch `TERMINATED`. `recover(name)` requires an explicit operator action and returns to `DISCONNECTED`, **not** to a connected worker or verified safe hardware. `disconnect_all()` attempts every connected worker and reports per-device failures. `terminate_all()` quarantines all registrations, including disconnected ones, and kills workers without freeing ownership. Kills are not hardware emergency-off commands.
- Session-bound driver-shaped live proxies (`source.set_frequency(...)`, `source.frequency`, `vna.get_trace(...)`), with `source.session` retaining explicit GET/SET/CALL. Run sessions use `run.instrument(name)`. GET/SET support declared keyword arguments. Only declared settings/operations are callable; invalid names/argument names fail before worker dispatch. The protocol uses 64 KiB JSON control envelopes and up to 16 inline numeric NumPy arrays / 8 MiB per result, suitable for VNA traces **but not digitizer streaming**.
- `clear_instruments()` persists a blank inventory only after all devices are disconnected, no workers remain, and no sessions/run exist. Normal service shutdown disconnects workers but retains registrations. Interactive headless CLI `shutdown` disconnects, clears, then exits only on success; Ctrl+C retains inventory. Simulator-only startup `-c`/`--clean` bypasses reconciliation and discards saved inventory/run state after acquiring the single-instance lock.
- Optional pyqtgraph/PySide6 inventory GUI: connection and ownership status; state-relevant Connect, Disconnect, Recover and Terminate actions; Disconnect All, Clear Instruments and Terminate All. Registration remains in the notebook. No instrument settings or data access. Closing the GUI leaves the service running; headless operation needs no Qt. Successful status polls are silent on the operator console.
- V2 `.auspex` dataset store (`v2/src/auspex_v2/data/`): **format version 2** uses self-describing `.dat` files with embedded value/coordinate arrays and names/units, including dependent grids and ragged offsets; direct file reads work without a manifest. A versioned manifest indexes published datasets; an optional JSON settings snapshot is separate. One exclusive writer owns atomic publication. Old V2 format version 1 and V1 files are not read. An optional dark [DataBrowser](v2/src/auspex_v2/data/data_browser.md) watches multiple OS folders for direct `.auspex` children (or adds individual runs), manually refreshes all inventories, plots published 1D datasets with pyqtgraph, and inspects nested metadata; multidimensional/ragged datasets remain visible but not plotted. See [data guide](v2/src/auspex_v2/data/data.md).
- Filter slice (`v2/src/auspex_v2/filters/`): in-process DAG reference, single-worker harness, and a dedicated-thread `FilterServer` supervising multiple spawned passthrough/complex-average workers. The graph supports single-ingress fan-out, overlapping windows, direct shared-memory edges, bounded JSON notification queues, named bounded results, lossy preview sinks, graph-wide update barriers with filter-local revisions, and cancellation/failure cleanup. `backpressure=True` waits; `False` fails on required capacity exhaustion and exposes a latched error/failure event to the runner. The runner owns windows; each averager owns its groups and rejects incomplete run end. Tests include independent group sizes, blocked-producer cancellation/worker death, buffer overflow, local revisions, memory cleanup, and a multi-worker simulated-VNA smoke test. The runner can label batches with explicit scan IDs and sweep positions and close scans; groups cannot cross scan boundaries. Required named writer sinks feed a **single spawned store-owner process** that stages bounded scans and acknowledges self-describing dataset publication at scan end. Regular Cartesian sweeps become named axes; irregular/repeated paths retain a point axis, and changing-length rank-one traces use ragged offsets. Whole assembled scans cannot yet be sent back through graph filters; publication assembles in bounded memory and is not an out-of-core benchmark. An optional, standalone dark PySide6 [graph viewer](v2/src/auspex_v2/filters/inspection.md) can attach through an explicitly configured local, read-only Unix socket and manually refresh topology, schemas, and last-acknowledged filter configurations; it has no measurement plotting or editing. See [filter guide](v2/src/auspex_v2/filters/README.md).

- Offline [experiment compiler](v2/src/auspex_v2/experiment/experiment.md): symbolic sequence builder, fixed/joint sweeps in V1 order, per-axis hooks, conditions and bounded loops, explicit WAIT lowering, detached versioned JSON plans, `explain()`, and a deterministic fake executor. Tests load and execute a saved plan in a fresh process. The review pass separates normalization, read-only validation, and instruction-ID assignment; tracks parameter availability across hooks/branches; detaches declaration metadata; accepts normalized NumPy settings; rejects incompatible known comparisons; and isolates fake command arguments/readbacks. Optional `InstrumentRef(driver=...)` enables driver-shaped assignment/getters/calls using the shared instrument proxy with a recording backend; explicit declared-member checks apply without constructing a driver. The minimize-surprise pass protects declared members/frozen recording configuration, adds explicit unswept runtime `seq.set_parameter()` updates with binding SET/WAIT and type/bounds checks, fixes proxy driver-keyword collisions, completes reflected arithmetic/unary negation, and expands `explain()` summaries. The publication bridge now compiles class-level `OutputConnector` declarations, explicit `seq.publish(data=..., axes=...)`, internal `setup_pipeline()` or warning-on-override external connections into detached version-2 plans with validated pipelines. Version-1 saved plans remain loadable. `PipelineExecutor` runs the saved unit through real filter workers/storage with injected offline command results and virtual waits; it is not a live hardware runner or service. Tests execute a saved unit in a fresh process, verify scan sealing before teardown and finalization waits afterward, and preserve completed data despite teardown failure. Example: `v2/examples/compiled_publication.py`.

- Standalone storage and [manual processing](v2/src/auspex_v2/filters/manual.md): documented direct `AuspexStore` writes, a whole-window `ManualPipeline` wrapper, and explicit bounded `BufferSpec` sinks with completed-output `receive`/`drain`/`view`. Buffers warn when full, preserve required backpressure/fail semantics, and retain independent arrays after graph shutdown. Synthetic example: `v2/examples/manual_data.py`. No instrument ownership or filter-state readback is added.

- Reusable [pipeline definitions](v2/src/auspex_v2/filters/definitions.md): inert named inputs, V1-style connector-pair wiring, passthrough/complex-average definitions, writer/buffer sink definitions, schema propagation, basic structural checks, detached JSON snapshots and save/load. `ManualPipeline` consumes either a definition (with an input schema) or a compiled recipe; older recipe-based calls still work. Exact writer dataset names currently support one scan per execution. Multi-input and empty-source recipes are expressible/serializable but rejected by the current single-ingress runner before startup. Experiment publication/attachment now uses these same definitions. Example: `v2/examples/pipeline_definition.py`.

## Not implemented / safety limits

No real-device server worker, physical-device readback or safety verification on recovery, hardware interlocks, operator authentication beyond socket permissions, durable lab-notebook audit trail, typed operation argument schemas, persistent ExperimentServer and real plan runner, automatic run-level metadata/events or settings-change logging, appendable datasets, plot subscriptions/reconnect, multi-input joins, custom graph-worker filter admission, or shared-buffer digitizer acquisition. Direct drivers used outside the server bypass its lockout. Console output is transient, not a durable or secret-safe audit trail.
